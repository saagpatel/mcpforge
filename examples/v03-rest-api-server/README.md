# Customer Support API

An MCP server that integrates with a customer support REST API to manage tickets, notes, service status, and triage workflows.

Generated by mcpforge.

## Components

### Tools


#### `list_tickets`

List all support tickets, optionally filtered by status or assignee.





Parameters:

- `status` (`str | None`, optional): Filter tickets by status (e.g. 'open', 'closed', 'pending'), or None for all

- `assignee` (`str | None`, optional): Filter tickets by assignee username or ID, or None for all

- `page` (`int`, optional): Page number for paginated results

- `page_size` (`int`, optional): Number of tickets to return per page


Returns: `dict`


Error cases:

- API request timeout

- invalid status value

- authentication failure

- upstream API error




#### `get_ticket`

Fetch a single support ticket by its unique ID, including all metadata and current status.





Parameters:

- `ticket_id` (`str`): The unique identifier of the support ticket to retrieve


Returns: `dict`


Error cases:

- ticket_id not found

- invalid ticket_id format

- API request timeout

- authentication failure

- upstream API error




#### `create_note`

Add a note to an existing support ticket by ticket ID.





Parameters:

- `ticket_id` (`str`): The unique identifier of the ticket to annotate

- `body` (`str`): The text content of the note to add to the ticket

- `author` (`str | None`, optional): Name or identifier of the note author; defaults to the API token owner if None

- `internal` (`bool`, optional): Whether the note is internal-only (not visible to the customer)


Returns: `dict`


Error cases:

- ticket_id not found

- body is empty

- API request timeout

- authentication failure

- upstream API error





### Resources


- `support://service-status`: Read the current service status and any active incidents from the support API.



### Prompts


- `triage_ticket`: Generate a structured triage analysis for a given support ticket to help agents prioritize and route it.

- `draft_customer_reply`: Draft a professional, empathetic reply to a customer based on the ticket context and a proposed resolution.



## Setup

Prerequisites:

- Python 3.12+
- uv
- FastMCP 3.x


Copy `.env.example` to `.env` and fill in the required values:

```bash
cp .env.example .env
```

Required environment variables:


- `SUPPORT_API_BASE_URL`

- `SUPPORT_API_TOKEN`

- `SUPPORT_API_TIMEOUT_SECONDS`



Install and test:

```bash
uv sync
uv run pytest
```

## Run Locally

Direct Python:

```bash
uv run python server.py
```

FastMCP stdio:

```bash
fastmcp run server.py
```

FastMCP HTTP:

```bash
fastmcp run fastmcp.json --transport http --host 127.0.0.1 --port 8000
```

## MCP Client Configuration

Local stdio client config:

```json
{
  "mcpServers": {
    "customer-support-api": {
      "command": "uv",
      "args": ["--directory", ".", "run", "python", "server.py"]
    }
  }
}
```

HTTP client config:

```json
{
  "mcpServers": {
    "customer-support-api": {
      "url": "http://localhost:8000/mcp/",
      "transport": "streamable-http"
    }
  }
}
```

## Security Notes

- Keep secrets in environment variables; never paste API keys into prompts.
- Require approval for sensitive write, delete, or external-send actions.
- Connect remote MCP clients only to trusted servers and review shared data.
- Do not pass MCP client bearer tokens through to downstream APIs.
- Log and review data sent to third-party services when running remotely.
